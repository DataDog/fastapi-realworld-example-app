# AI Agents Documentation

This file is the canonical reference for AI coding agents working in this repository. It covers project setup, architecture, testing, tooling, and agent-specific guidance.

## Quick Start

```bash
# 1. Start PostgreSQL (REQUIRED for tests and development)
# Note: Database works without .env file (uses defaults)
docker compose up -d db

# 2. Install dependencies
uv sync

# 3. Setup environment (optional - create from example)
cp .env.example .env
# Edit .env and set SECRET_KEY:
# SECRET_KEY=$(openssl rand -hex 32)

# 4. Run migrations
alembic upgrade head

# 5. Run tests
./scripts/test
# or with specific Python version
hatch run -vvvv +py=3.14 unit_tests:test

# 6. Start development server
uvicorn app.main:app --reload
```

## Project Overview

FastAPI implementation of the RealWorld backend API specification (Conduit). This is a blogging platform with articles, comments, user profiles, authentication, and favorites. The project uses async PostgreSQL with asyncpg and follows a clean architecture pattern.

**Note**: This project uses **uv** for dependency management (migrated from Poetry). uv is a fast Rust-based package manager from the Astral team (creators of Ruff).

**⚠️ Database Requirement**: All tests and development require PostgreSQL running via `docker compose up -d db`

### Testing

**Running Tests:**

```bash

./scripts/test

# Run specific test file
./scripts/test tests/test_api/test_routes/test_users.py

# Run specific test function
./scripts/test tests/test_api/test_routes/test_users.py::test_user_can_not_take_already_used_credentials

./scripts/test-cov-html

# Test against specific Python version using Hatch (CI command)
hatch run -vvvv +py=3.14 unit_tests:test

hatch run +py=3.9,3.10,3.11,3.12,3.13,3.14 unit_tests:test
```

### API Spec Tests (Postman/Newman)

Run the full RealWorld API specification tests locally:

```bash
# Make sure database is running
docker compose up -d db

# Run API spec tests with default Python version (3.14)
./scripts/run-postman

# Run with specific Python version
./scripts/run-postman 3.12

# Run with custom port
PORT=8080 ./scripts/run-postman

# Run with custom API URL
APIURL=http://localhost:8080/api ./scripts/run-postman
```

**What it does:**
1. Creates/verifies Hatch environment for specified Python version
2. Checks database connectivity
3. Runs Alembic migrations (`upgrade head`)
4. Starts uvicorn server in background
5. Waits for server to be ready
6. Runs Postman API spec tests via Newman
7. Cleans up: stops server and downgrades database (`downgrade base`)

**Environment variables:**
- `SECRET_KEY` - JWT secret key (default: `secret_key`)
- `DATABASE_URL` - PostgreSQL connection string (default: `postgresql://postgres:postgres@localhost/postgres`)
- `PORT` - Server port (default: `8000`)
- `APIURL` - API base URL for tests (default: `http://localhost:8000/api`)

## Architecture

### Directory Structure

- `app/api/` - Web layer with routes, dependencies, and error handlers
  - `dependencies/` - FastAPI dependency injection functions for auth, database, resources
  - `routes/` - API endpoints organized by resource
  - `errors/` - Custom error handlers for HTTP and validation errors
- `app/core/` - Application configuration and startup/shutdown events
  - `settings/` - Environment-specific settings (dev, prod, test)
- `app/db/` - Database layer
  - `repositories/` - Data access layer with CRUD operations
  - `queries/` - SQL queries using aiosql (`.sql` files in `queries/sql/`)
  - `migrations/` - Alembic database migrations
- `app/models/` - Pydantic models
  - `domain/` - Core business models (Article, User, Comment, Profile)
  - `schemas/` - Request/response schemas for API endpoints
- `app/services/` - Business logic (authentication, JWT, security)
- `app/resources/` - String constants for error messages and responses

### Key Architectural Patterns

**Settings Management**: Environment-based configuration system using `APP_ENV` variable to select between dev/prod/test settings. All settings classes inherit from `BaseAppSettings` and are managed through `get_app_settings()`.

**Database Access**: Uses dependency injection pattern where:
1. `_get_db_pool()` retrieves connection pool from FastAPI app state
2. `_get_connection_from_pool()` acquires connection from pool
3. `get_repository(repo_type)` factory returns repository instances with injected connections

**Repository Pattern**: All data access goes through repository classes (ArticlesRepository, UsersRepository, etc.) that inherit from `BaseRepository` and take an asyncpg Connection. Repositories use either:
- PyPika query builder (in `app/db/queries/tables.py`) for dynamic queries
- aiosql SQL files (in `app/db/queries/sql/*.sql`) for static queries

**Model Inheritance**:
- `RWModel` (domain models): Base Pydantic model with camelCase alias generation
- `RWSchema` (API schemas): Extends RWModel with `from_attributes=True` for ORM compatibility

**Route Organization**: Routes follow REST principles with dependencies injected for authentication (optional/required) and database access. Main router in `app/api/routes/api.py` aggregates all route modules.

**Testing**: Tests use `FakeAsyncPGPool` wrapper for database cleanup between tests. Fixtures in `conftest.py` provide authenticated clients, test users, and test articles.

## Modern Python Tooling Stack

This project uses cutting-edge Python tooling for speed and developer experience:

- **uv**: Ultra-fast dependency management (10-100x faster than pip/poetry)
  - Replaces: pip, pip-tools, poetry
  - Lock file: `uv.lock`
  - Install: `curl -LsSf https://astral.sh/uv/install.sh | sh`

- **Ruff**: Fast linter and formatter (10-100x faster than Black + flake8)
  - Replaces: Black, isort, flake8, autoflake, pyupgrade
  - Configuration in `pyproject.toml` under `[tool.ruff]`

- **Hatch**: Environment and testing manager
  - Multi-version Python testing (3.9-3.14)
  - Configuration in `hatch.toml`

- **Hatchling**: Build backend supporting PEP 660 editable installs
  - Configuration in `pyproject.toml` under `[tool.hatch.build]`
  - Packages: `["app"]` (specifies the Python package location)

- **mypy**: Static type checking with strict configuration
  - Configuration in `setup.cfg` and `pyproject.toml`

## Testing Strategy

### Database Requirements

**Tests require a running PostgreSQL database.** The test suite will fail with connection errors if the database is not available.

```bash
# Start database before running tests
docker compose up -d db

# Then run tests
./scripts/test
# or
hatch run -vvvv +py=3.14 unit_tests:test
```

### Test Configuration

- **Database**: PostgreSQL required (start with `docker compose up -d db`)
- **Connection**: Configured via `DATABASE_URL` environment variable
  - Default: `postgresql://postgres:postgres@localhost:5432/postgres`
  - Can be overridden in `.env` file or `app/core/settings/test.py`
- **Coverage target**: 100% (project goal; not strictly enforced by pytest config)
- **Parallel execution**: Tests run in parallel using pytest-xdist
- **Database cleanup**: State is reset between tests using FakeAsyncPGPool wrapper
- **Test isolation**: Each test gets a clean database state

### Common Test Issues

**Connection Error:** `psycopg2.OperationalError: could not connect to server`
- **Solution:** Start database with `docker compose up -d db`
- **Check status:** `docker compose ps`
- **View logs:** `docker compose logs db`

**Port Already in Use:**
- **Solution:** Stop existing PostgreSQL: `docker compose down`
- **Or use different port:** Modify `docker-compose.yml`

## Python Version Support

This project supports Python 3.9 through 3.14:
- **GitHub CI**: Tests run automatically on all supported Python versions using `hatch run -vvvv +py={version} unit_tests:test`
- **Local testing**: Use Hatch to test across all Python versions locally
  - `hatch run -vvvv +py=3.12 unit_tests:test` - Test specific Python version
  - `hatch run +py=3.9,3.10,3.11,3.12,3.13,3.14 unit_tests:test` - Test all versions
- All versions are tested in CI for both unit tests and API spec compliance tests
- **Hatch configuration**: Located in `hatch.toml` (separate from `pyproject.toml`)
  - Defines `unit_tests` environment with matrix for all supported versions
  - Defines `lint` environment for code quality checks
- The `unit_tests:test` script automatically runs `alembic upgrade head` before running pytest

### Best Practices for AI Agents

AI agents should:
- Follow the established architecture patterns (repository pattern, dependency injection)
- Maintain 100% test coverage
- Use the modern Python tooling stack (uv, Ruff, Hatch)
- Respect the repository pattern and dependency injection
- Follow the testing strategy (database requirements, isolation, etc.)

Human developers using AI agents should:
- Review all AI-generated code before committing
- Verify that tests pass and coverage remains at 100%
- Ensure AI follows the architecture patterns described in this file
- Check that AI agents use the correct tooling (uv, not poetry; Ruff, not Black)
